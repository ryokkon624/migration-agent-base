Sprint 08 Review

#4 — [E2] カートの追加/数量更新/削除/表示ができるようにする

Sprint 08 #4 feature E2 / F2.1 database backend frontend
As a 買い物客（未認証を含む）　I want to 商品をカートに入れ、数量を変え、削除し、内容を確認したい　So that 購入前に注文内容を組み立てられる

なぜこの改修が必要だったか

as-is（レガシー）の問題

Struts 1 の Cart.java はセッション内オブジェクトのみでDB永続化がなく、以下の課題があった。

  • 幽霊行バグ: itemMap（itemId→CartItem）と itemList（PagedListHolder）の二重構造で、数量0以下の削除が itemList からのみ行われ itemMap に残存する（同itemId再追加で数量が想定外に加算される）
  • 数量更新は「リクエストパラメータ名＝itemId」という暗黙規約で、明示的なAPI契約がない
  • 不正な itemId は getItem が null を返しそのまま item.getItemId() でNPE
  • 在庫充足の強制がなく、在庫を超える数量でもカートに入れられる（過剰販売の温床）
改修前（as-is）
カート = セッション内Javaオブジェクトのみ、DB永続なし
itemMap/itemList二重構造 → 幽霊行desync（ID-17）
数量更新はパラメータ名=itemIdの暗黙規約
不正itemId → NPE
在庫充足チェックなし
→
改修後（after）
t_cart/t_cart_item（DB永続）＋未ログインはPinia/localStorage
単一表+UNIQUE(cart_id,item_id)で幽霊行を構造的に排除
明示的な {itemId, quantity} REST API
不正itemId → 404（SBD-10）
在庫上限=在庫数をserver-sideで強制（qtyは非露出のまま・ID-28）

動作確認ポイント（ユーザー確認用）

  • 1
    商品詳細画面で「Add to Cart」を押すとカートに追加され、ヘッダーの件数バッジが増えること 在庫切れ商品（例: Tiger Shark）はボタンが非活性になっていることも確認
  • 2
    カート画面（/cart）で数量変更・削除すると即座に反映され、小計が正しく再計算されること 数量を0にすると行が消えること（AC2）
  • 3
    未ログインでカートに商品を追加した後ログインすると、内容がサーバー側に引き継がれる（マージ）こと ログイン前にサーバーカートに同じ商品があった場合は数量が加算されること
  • 4
    在庫数を超える数量を入力するとエラーメッセージが表示され拒否されること 未ログイン状態でも同じ検証が効くこと（在庫数自体はUIに一切表示されない）
  • 5
    未ログインでもカート画面（/cart）自体は開けること 認証が必要なのはカートAPIの呼び出しのみで、画面自体は公開ルート（D2）
