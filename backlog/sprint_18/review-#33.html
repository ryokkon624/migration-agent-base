Sprint 18 Review · Bug Fix

#33 — 保護ルートのリロード/直リンクで
ログイン済みでもサインオンに飛ばされる

Sprint 18 #33 bug frontend

発生事象

修正前（バグあり）
https://localhost:5173/account/orders （直リンク/リロード）
Home Catalog Cart Hi, demo_user
→ /signon?redirect=/account/orders へリダイレクト
ヘッダーは認証済み表示のまま、なぜかサインオン画面に飛ばされる
修正後（正常）
https://localhost:5173/account/orders （直リンク/リロード）
Home Catalog Cart Hi, demo_user
→ Order History 画面がそのまま表示される
リダイレクトは発生せず、注文履歴が表示される

原因分析

🔍 router install が「再水和(rehydration)完了」より先に実行されていた

main.ts の bootstrap() は、Cookie は有効でも Pinia の認証state はリロードで揮発するため、/api/auth/me を呼んで再水和してから画面を描画する設計だった。しかし app.use(router)（router install）が再水和の await より前に実行されていたため、vue-router が install 時に開始する初期ナビゲーションで authGuard が isAuthenticated=false のまま評価され、有効なセッションでも signon へ誤誘導していた。

処理順 修正前の実行順序（誤り） 修正後の実行順序（正しい）
1 app.use(router) ※初期ナビ開始 ≠ await 再水和(/api/auth/me)
2 await 再水和(/api/auth/me) ≠ app.use(router) ※初期ナビ開始
3 app.mount('#app') = app.mount('#app')

コード上のコメント（「マウント前に /api/auth/me で再水和してから描画する（ガード誤判定防止）」）は当初からその意図で書かれていたが、app.use(router) の位置がこの意図に反していたため実際には効いていなかった。

改修内容

src/main.ts +6 / -1
13 app.use(createPinia())
14 app.use(i18n)
15- app.use(router)
// ...(コメント省略)...
22 await Promise.all([primeCsrfToken(), useAuthStore().fetchCurrentUser()])
24+ // #33: app.use(router)はここまで遅延させる。vue-routerはinstall時に初期ナビゲーションを
25+ // 開始しauthGuardを評価するため、再水和(fetchCurrentUser)完了より前にinstallすると
26+ // isAuthenticated=falseのまま保護ルートが誤ってsignonへ誘導される(リロード/直リンクで再現)。
27+ app.use(router)
29 app.mount('#app')
💡 pinia/i18nの install は再水和の useAuthStore() 呼び出しより前に必要なため現行位置のまま維持し、router のみ再水和 await の後ろへ移動した。
